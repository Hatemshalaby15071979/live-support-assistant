## 2. What this product is (and is not)

LIVE Support Assistant answers frontline support-agent questions from a **tenant's own procedures**.
The answering path is fully on-device: pinned MiniLM embeddings (`Xenova/all-MiniLM-L6-v2`
@ `751bff37182d…`, q8) → passage-level cosine retrieval → a **deterministic confidence gate**
(top-1 must clear an absolute floor AND beat top-2 by `minMargin`, default 0.18) → a sourced
answer; otherwise a **handoff to a human with no procedure text shown**. There is **no generative
model in the answering path**.

- **Is not:** a chatbot/LLM product, a self-serve SaaS (no billing, no sign-up), or a
  production-proven system. Positioning: validated on simulated tenants, safety-first by design,
  ready for a **shadow-mode pilot** (`docs/PRODUCTION_STATUS.md`).
- **Deployed demo:** https://dist-omega-black-31.vercel.app/ — **sign-in required**, no guest
  account. Never present it as an open demo.
- Multi-tenant via Supabase RLS; encrypted, signed, versioned SOP bundles; publish path refuses
  contradictory corpora with **HTTP 422**; telemetry with per-candidate evidence stored in
  `payload jsonb`.

## 5. Architecture in one page

**Decision path (client):** pinned MiniLM `embedQuery` → passage cosine `searchTopK` →
`evaluateGate` (`packages/core/src/gate.ts`; outcome taxonomy `accepted | blocked` +
`GateBlockReason`) → `buildAgentView`. Escalations expose **no** procedure text/title/suggested
reply. The client refuses a bundle whose manifest model differs from its loaded model
(MC-06; `apps/web/src/bundle-client.ts` passes `LOADED_MODEL` into `installBundle`).

**Bundle pipeline (server):** author procedures → conflict lint (same-category numeric policy
conflicts; English number words only — `docs/KNOWN_ISSUES.md` §2) → publish edge function signs +
encrypts a versioned bundle; contradictory corpus → **HTTP 422**; devices enroll (tenant-coupled
KEK salt), install monotonically, refuse tamper/replay/foreign keys (31-check suite).

**Command Center (Supabase):** schema + RLS in `supabase/migrations/`; RBAC 99-probe suite;
telemetry `payload jsonb` stores `topCandidates` for **every** query — this is how deployed gate
decisions are read back without UI changes (`tooling/browser/run-simulated-deployed-evaluation.mjs`).
Deployed SOP ids are DB UUIDs; map them to corpus slugs via `corpus.sops` before comparing with
local harness output (historical bug source).

**Verification apparatus:** gate `tooling/run-verification.mjs` (17 suites, §3.3);
`verify:db` = `tooling/db/verify-phase7.sh` (needs Docker; suite 4 = F-1 accepted red with
`f1_record_guard`; suite 6 = `rls_surface_audit.sql` tripwire); `verify:hosted` (discovery-based
helper cleanup + residue tripwire); `audit` gate (baseline `tooling/audit-baseline.json` is EMPTY
→ any new production advisory fails); Market Twin (`tooling/market/` — smoke gated, standard rung
nightly-shaped but **no scheduler exists anywhere**); eval harnesses (Vite-root + headless Chrome
over CDP; pinned batch `chaos-500.json` SHA `717c40dc`, never edit; reports refuse to overwrite a
run label).
